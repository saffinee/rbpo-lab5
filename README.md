# парковка (лаба 5)

продолжение лабы 4: пользователи, машины, парковки и абонементы остались прежними. вместо basic auth приложение выдаёт jwt access и refresh. права пользователя и администратора, а также проверки доступа к своим данным сохранены.

## запуск

1. настроить `.env` по образцу `.env.example`: указать базу лабы 4 и добавить `JWT_SECRET`. ключ можно получить командой `openssl rand -base64 32`.
2. для существующей базы лабы 4 добавить таблицу сессий: `psql -d parking_lab4 -f db/lab5.sql` от пользователя с правами на создание таблиц. данные не удаляются. для новой базы можно использовать `db/init.sql`.
3. запустить приложение: `mvn spring-boot:run`.

## токены

- `POST /api/auth/register`: `{"name":"Иван","email":"ivan@example.com","password":"Password123!","deviceId":"телефон"}`. пароль — не менее 10 символов, с латинскими буквами обоих регистров, цифрой и спецсимволом. `deviceId` необязателен.
- `POST /api/auth/login`: `{"email":"ivan@example.com","password":"Password123!","deviceId":"телефон"}`. регистрация и вход возвращают `username`, `accessToken` и `refreshToken`.
- запросы к API: заголовок `Authorization: Bearer <accessToken>`. access действует 15 минут.
- `POST /api/auth/refresh`: `{"refreshToken":"..."}`. старый refresh получает статус `USED`, новая пара сохраняется отдельной записью `ACTIVE`. повторно использовать старый refresh нельзя. срок refresh — 7 дней.
- `POST /api/auth/logout`: `{"refreshToken":"..."}`. refresh получает статус `REVOKED`; access действует до истечения срока.

в таблице `user_sessions` хранится история пар токенов и время их истечения. пароль по-прежнему хранится в виде bcrypt-хэша, а секрет jwt и токены не нужно добавлять в git.
